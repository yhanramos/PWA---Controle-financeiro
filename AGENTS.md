# Orientações do projeto

- Ler README.md e documentos em docs/ antes de alterar o projeto.
- Não executar comandos de build nem de teste sem uma nova instrução explícita que altere essa restrição.
- Escrever arquivos em UTF-8.
- Estilos de produto em SCSS com herança; manter a entrada Tailwind separada.
- Branches devem usar fix/, perf/, feat/, remove/ ou chore/. Nunca usar codex/.
- Trabalhar por etapas do docs/ROADMAP.md. Não apresentar placeholders como funcionalidades concluídas.
- Nunca persistir secrets no repositório nem criar serviços de produção com dados mockados.
